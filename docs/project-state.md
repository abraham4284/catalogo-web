# Estado vigente

Current phase: F9 completada.

- Frontend: React + TypeScript + Vite Storefront; shell público compartido con StoreLayout, Header y Footer neutrales y responsive.
- Routing: `/`, `/productos`, `/productos/:idProduct`, `/carrito` y `*` dentro del layout; detalle consume API real, Not Found con regreso al inicio. IDs de producto inválidos no montan fetching ni hacen requests. Header enlaza al carrito sin store ni contador.
- Environment: `config/env.ts` valida de forma lazy VITE_CATALOG_API_URL (prefijo completo /api/public) y VITE_WHATSAPP_NUMBER (público, solo 8–15 dígitos internacionales, sin default). `.env.example` documenta ambas; configuraciones locales ignoradas. Build funciona sin datos reales configurados.
- Backend: backend comercial Cajora desplegado separadamente.
- Catalog API: frontera para negocio, categorías, listado y detalle, con Zod y tipos derivados. Contrato F9: stockAvailable entero no negativo del depósito principal/default activo; listado con secondaryImageUrl nullable, detalle con gallery y richContent nullable v1 (sin requerir secundaria). Sin endpoints administrativos ni requests de detalle por card. Se conservan reglas de paginación, errores/cancelación y totalPages >= 1/sortOrder >= 0.
- Catalog UI: Home consume negocio/categorías/primeros 8 productos; catálogo consulta 24 por página con filtros URL. ProductCard única con descripción corta (clamp CSS), portada/secundaria al hover de puntero fino y acciones rápidas. ProductGrid ofrece renderActions; app/compositions integra agregar y consulta individual para ambas páginas. Disponible requiere available && stockAvailable > 0; nunca se muestra stock exacto. Grid prioriza una columna en anchos pequeños, dos desde 540 px, tres md y cuatro xl.
- Product detail: descripción opcional como introducción, acciones de agregado/consulta y rich content bajo el bloque galería/datos. RichContentRenderer genera headings h2/h3, párrafos, listas y specs dl a partir del schema v1; sin HTML arbitrario. Galería conserva portada/orden/deduplicación y miniaturas accesibles. ProductImage compartido con carrito para fallback. Fetching abortable; cambio de ID reinicia contenido; 404 presenta producto no disponible.
- Catalog filters: search/category/page en URL, parsing seguro de parámetros inválidos; cambio de búsqueda/categoría reinicia página y paginación conserva filtros. Página superior a totalPages redirige a la última válida con replace, conservando filtros. Requests abortables con protección de respuestas obsoletas.
- Database: DB_COMERCIO independiente de Cajora SaaS DB.
- Brand: no definida; ningún nombre temporal representa branding final.
- Cart: Zustand + localStorage, clave catalogo-web-cart, versión 2; snapshot idProduct/name/price/imageUrl/available/stockAvailable/quantity. Add/increment limitados por disponibilidad y stock; decrement mínimo 1. Filas con imagen principal 1:1/fallback y un enlace lógico imagen/nombre. Totales derivados, eliminar/vaciar y empty conservados. Persistencia v1, corrupta o incompatible produce vacío seguro; almacenamiento bloqueado/lleno deja store en memoria usable.
- Cart snapshot: reconcileItem actualiza snapshot existente al recibir productos en Home/Catalog/detalle, sin incremento/recorte de quantity ni escrituras idénticas. Stock que baja a cero conserva item no disponible; exceso de quantity muestra aviso y bloquea consulta normal hasta reducir/eliminar. Sin polling, N+1 desde cart, reservas, órdenes ni garantía de stock en tiempo real.
- Checkout: handoff WhatsApp implementado desde /carrito con enlace wa.me seguro en nueva pestaña. Mensaje puro usa snapshot local, cantidades, precios unitarios, subtotales y total estimado; pide confirmar precio/disponibilidad. Sin contacto configurado, CTA deshabilitado con mensaje neutral. No vacía automáticamente el carrito, no envía mensajes automáticamente ni crea órdenes/ventas backend.
- Individual inquiry: ProductInquiryLink cambia entre Consultar ahora/Consultar disponibilidad. Contrato propio name/price/available, normaliza nombre y usa precio publicado; sin stock ni IDs internos. Configuración lazy, URL codificada y noopener/noreferrer; no modifica carrito ni backend.
- Customer authentication: fuera de alcance.
- Blog: posibilidad futura, fuera del MVP.
- Architecture: features + Clean Architecture pragmática; shadcn en shared.
- Accessibility / responsive: revisión estructural aplicada; Header mobile en dos filas, controles de cantidad de 44 px y wrapping seguro en main/filas. StoreRoute enfoca main al cambiar pathname, sin robar foco por queries; skip link verificado. Miniaturas conservan nombre accesible en botón e imagen interna decorativa. Categorías se cargan solo al montar listado, independientes de productos por query; se conservan durante loading/error de productos.
