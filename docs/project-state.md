Fetching abortable; cambio de slug reinicia contenido; 404 presenta copy neutral sin inferir motivo ni usar texto backend. availabilityNote no vacía se muestra como texto plano en cualquier estado. Límites de rich content alineados al contrato definitivo.

Snapshot idProduct/slug/name/priceSale/priceWholesale/imageUrl/availabilityStatus/stockAvailable y quantity; los importes y el nivel son derivados, no persistidos. v3 válido migra price a priceSale y priceWholesale a null hasta revalidar; se escribe v4 con la siguiente mutación. v1/v2/futuras, JSON corrupto, IDs/slugs duplicados y campos inválidos producen vacío seguro; storage bloqueado/lleno conserva memoria usable. Imagen/nombre forman un único enlace /productos/<slug>. Agotado/encargo permanecen visibles con cantidad deshabilitada; exceso de quantity mantiene aviso, permite disminuir/eliminar y bloquea checkout.
- Cart snapshot: Revalidación coordinada en app/compositions: al montar /carrito con items, cambiar el conjunto idProduct+slug o reintentar. Verifica ID/slug de respuesta; identidad distinta, nombre vacío, 404 ambiguo, red/error HTTP o contrato inválido conservan snapshot y marcan fallo. Éxitos parciales actualizan precio/nombre/imagen/status/stock. AbortController y comprobación del conjunto actual impiden reconciliar corridas obsoletas. Quantity, reconcile y renders no disparan requests. Estado runtime loading/success/error con failedProductIds y retry, sin persistencia.
